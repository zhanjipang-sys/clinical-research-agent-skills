# 皮肤外科交互教学图（教学层技能）

本技能只负责**教学层**：一张图教什么、先让学习者猜错什么、动手改哪个变量、看哪些读数、怎样算验收合格。
它不负责渲染工艺本身——需要等距立体、机械质感、剖面或爆炸视图时，转 `local-anatomy` 技能执行；
平面几何题材（皮瓣设计线、角度、转位）用轻量 2D SVG 即可，不要动用重型等距工具包。

方法来源与许可边界：教学规格法、机制↔渲染器路由与双门验收借鉴 ywEdAi/teachable-figures（2026，
GitHub）的教学层设计。注意：该仓库根目录无总许可证，其原创课程文案与示例页**未明确授权**——
只可借鉴方法与结构，**不得成段搬运它的课程文案、示例文本或页面**；本技能与据此制作的页面
文字须全部原创。仓库内置的 Anatomy、iso-figure 两个工具包为 MIT，但本技能不复制它们。

## 一、教学规格契约（动手画图之前先写完，缺一不可）

每张图先落一份 spec，字段如下：

1. **结论（anchor）**：学习者离开页面时应能说出的一句话。页面标题与页首导语从它来。
2. **误解（misconception）**：一个听起来合理、但操作图形就能证伪的错误直觉。没有误解的题目不要做成交互图。
3. **预测题（predict）**：三选一，选项中**必须包含误解项**（即按错误直觉会选的那一项），且只有一个正确答案。预测在动手之前提交，提交后锁定。
4. **变量（cause）**：学习者能改变的 1–3 个原因（滑杆、开关、按钮组、拖动）。变量必须真是机制的因，不是装饰。
5. **读数（effect）**：可观察的结果量，每个读数在界面上就地给出定义（如「有效推进＝朝初始方向的净位移」）。事实数值与示意参数必须分开标注：示意参数写明「示意参数/示意模型」，不得冒充实测值。
6. **单一真值模型（derive()）**：写一个纯函数 `derive(state) → 全部读数与绘图参数`。图形、读数、判定、解释中引用的数字**全部**由它产出，禁止在渲染或文案里另算一份。解释里写死的对照数字必须与 derive() 在对应状态下的输出一致（交付前逐个核对）。
7. **解释（insight）**：操作达标后才揭晓。合格的解释必须包含两条因果链（为什么读数这样变、为什么代价那样变），并给出模型的适用范围。
8. **模型边界（caveat）**：模型没算什么（弹性、潜行松动、张力再分布……）、哪些是经典教材结论、哪些是示意估算，写在解释区内，不藏着。
9. **迁移题（transfer）**：一个**没有控件**的新情境问题，学习者先自己想，再展开参考答案。答案必须只能用本图机制推出，不能靠新知识。

作者自查三问：什么算「一次有意义的尝试」（揭晓解释的触发条件，写进交互逻辑）？预测错的人被哪个读数当场纠正？迁移题换了情境还成立吗？

## 二、机制类型 ↔ 渲染器路由

先定机制类型（这张图教的因果是什么），再按主体形态选渲染器，两者独立决定：

| 机制类型 | 典型题材 | 首选渲染 |
|---|---|---|
| 刚体转位几何 | 旋转瓣、菱形瓣、Z 成形、双叶瓣 | 2D SVG 俯视示意（本技能默认） |
| 张力/顺应性权衡 | 推进瓣、潜行、减张缝合 | 2D SVG ＋ 定性指数（须标注示意模型） |
| 空间结构/层次 | 皮下层次、血管神经走行、切口深度 | 剖面或分层示意；等距走 local-anatomy |
| 器械与操作 | 持针器、缝合手法器械、激光手具 | local-anatomy（等距机械路线） |
| 有机形态 | 器官、皮瓣血供区、瘢痕形态 | **见下方红线** |

**红线（借自 Teachable Figures 对 Anatomy 盲区的纠偏）：有机形态与柔性组织不许用几何零件硬套**——
不要把器官画成球、把皮肤画成盒子。需要表现有机形态时，走参考网格、轮廓描摹或专门插图；
宁可做一张诚实的平面示意图并标注「示意图」，也不要用等距零件拼一个假器官。

补充规则：

- 能用 2D 讲清的机制不上 3D；角度、弧线、转位这类平面几何，SVG 就是正确档位。
- 渲染工艺口径以被调用的渲染技能为准。本技能**不引入** Teachable Figures 仓内那份 Anatomy 副本，
  也不采用它的零件密度口径；local-anatomy 的零件数/审计规则只适用于仪器类 explainer，
  不适用于本技能的平面教学图（平面图的密度由教学需要决定）。
- 产出形态：一页一机制、自包含单文件 HTML、离线可用、原生控件（滑杆/单选/按钮），
  尊重 prefers-reduced-motion。

## 三、互动五步（每页固定结构）

1. **页首结论**：标题＋一段「结论先行」导语，让学习者带着判断去验证。
2. **先预测**：三选一（含误解项），提交后锁定，未提交不能揭晓解释。
3. **动手**：操作控件改变变量；图形与读数实时响应，只出自 derive()。
4. **观察与解释**：达到 spec 里定义的「有意义的尝试」条件后，对照揭晓预测对错并展开解释（含模型边界）。
5. **迁移**：页尾无控件的新情境题，先想后展开参考答案。

页脚固定小字：「教学示意图」＋模型性质说明（示意参数/经典结论的出处口径）。

## 四、双门验收（两道门分开过，缺一门不算交付）

**教学正确门**：
- 误解项确实被操作证伪，且证伪它的读数在界面上可直接读到；
- 解释中的每个数字与 derive() 输出逐个核对一致（含预测反馈里的对照数字）；
- 模型边界已写明；示意参数已标注，未冒充实测；
- 迁移题只能用本图机制回答，参考答案与机制一致；
- 医学事实只用已核准的经典结论（如 Z 成形教材延长率、Limberg 几何），存疑处停下上报，不自行编造。

**视觉保真门**：
- 初始态与至少一个操作态截图亲眼查：无文字溢出、无标签相撞、控件齐全、中文无误；
- 几何关系目测成立（等长边相等、角度标注与图形一致、转位前后瓣的位置关系正确）；
- 至少一页（或每页）抽查一个读数手算复核，与 derive() 对照；
- 移动窄屏（约 390 px）下布局不破。

注意：页面能在浏览器跑通、数值自洽，都不能替代亲眼看图这一项。

## 五、工作流程

1. 写 spec（第一节九个字段）→ 自己按三问自查。
2. 按第二节路由表选渲染器；平面题直接写 SVG 页面，空间/器械题转 local-anatomy 并把 spec 一并交过去。
3. 实现 derive() → 渲染只读 derive() → 接五步交互状态机（预测锁定、达标揭晓、重置）。
4. 过双门验收（第四节），截图存页同目录 `qa/`。
5. 交付说明里列：学习目标一句话、spec 中的误解是什么、哪些数字是示意参数、存疑点。

已按本技能制作的示例：`~/workspace/surgical-teaching/`（皮肤外科交互学习教程：旋转皮瓣、菱形皮瓣、Z 成形术、推进皮瓣四页＋索引），新页沿用其视觉与布局语言。
